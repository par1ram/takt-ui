# Takt

[Сценарии использования каждого компонента](docs/use-cases.ru.md)

Библиотека motion-компонентов для Next.js, React и Tailwind CSS. На главной странице можно попробовать каждый компонент, посмотреть его исходник и скопировать команду установки через shadcn CLI.

В [мессенджере курса](https://takt-ui.vercel.app/ru/messenger) можно попробовать каналы, личные сообщения, реакции и треды. Демо хранит переписку и черновики в памяти вкладки. Для подключения своего сервера передайте `messages`, `onSend(channelId, text, parentId?)` и `onToggleReaction(channelId, postId, emoji)`. Установите весь интерфейс через `@takt/course-messenger` или выберите отдельный компонент на странице.

В [разделе метрик](https://takt-ui.vercel.app/ru/metrics) есть три устанавливаемых компонента. Передайте в Latency Chart последовательность замеров P50/P95, в Conversion Funnel — численность по этапам, а в Cohort Retention — размер каждой когорты и число вернувшихся участников. Пропущенное измерение обозначается `null`.

Issue Board, Issue Table и Cycle Planner используют тип `TrackerIssue` из устанавливаемого файла `tracker-issues.tsx`. Передайте общий массив `issues` и обработчик `onIssuesChange`, чтобы синхронизировать доску, таблицу и план цикла. Для автономного трекера передайте `defaultIssues`. У задачи есть уникальный стабильный ID, название, статус, приоритет, оценка в баллах и необязательный ID цикла.

## Учебные компоненты

В [Code Exercise](https://takt-ui.vercel.app/ru/components/code-exercise) можно запустить шаблон, разобрать упавший тест и вернуться из цитаты к редактору. Встроенный пример компилирует регулярные выражения в отдельном браузерном Worker. Чтобы использовать свою среду, передайте `onExecute(source, cases, signal, onRunning)` и верните массив булевых результатов в порядке тестов. Ключ `draftKey` сохраняет черновик урока на устройстве. В Ask Tutor обработчик `onAsk(question, context)` получает вопрос и выбранные источники. Верните из своего сервера `{ text, citation: { title, locator, excerpt, href } }`. В каталоге показан демоответ.

## Локальный запуск

```sh
bun install
bun run dev
```

Адрес каталога выводится в терминале. На главной странице открывается английская версия, по пути `/ru` — русская. Для проверки production-сборки выполните `bun run build`, затем `bun run start`.

## Установка компонента в другой проект

В проекте с настроенными Tailwind CSS и shadcn/ui выполните `export TAKT_ORIGIN=https://takt-ui.vercel.app`. Например, для кнопки с магнитным эффектом выполните:

```sh
bunx shadcn@latest add "$TAKT_ORIGIN/r/magnetic-button.json"
```

CLI добавит исходник в каталог UI-компонентов, заданный в `components.json`, и установит зависимости. Команда в карточке компонента автоматически использует адрес открытого каталога.

Tailwind 4 собирает классы из TSX и общих файлов в `lib/`. В Takt точка входа стилей — `app/globals.css`, подключённая через общий `components/site-layout.tsx`. В другом проекте эту роль выполняет его собственный глобальный CSS с Tailwind и токенами shadcn. Через `shadcn add` вместе с выбранным компонентом копируются указанные в реестре вспомогательные файлы. При ручном копировании перенесите также его локальные импорты и установите зависимости. Классы появления и исчезновения используют `tw-animate-css`.

Палитра рядом с поиском меняет акцент каталога и сохраняет его в браузере. Для установленного компонента задайте `--primary` и `--primary-foreground` в теме приложения. Для фокуса и мягких выделений используются `--ring`, `--accent` и `--accent-foreground`. Светлая тема задаётся в `:root`, тёмная — в `.dark`.

Все компоненты библиотеки (105) принимают `className`. Например, `<InvitePeople className="w-80 rounded-2xl" />` меняет ширину и скругление формы приглашения. Цвета поверхности, текста и активных элементов задаются токенами темы shadcn.

В новом проекте начните с рекомендуемых настроек Next.js:

```sh
bun create next-app@latest my-app --yes
cd my-app
bunx shadcn@latest init
```

Для установки всех компонентов одной командой используйте `bunx shadcn@latest add "$TAKT_ORIGIN/r/takt.json"`. Для русских текстов замените `/r/` на `/r/ru/`. Компоненты импортируются по отдельности из каталога UI приложения.

## Размещение на Vercel

Русский каталог опубликован на [takt-ui.vercel.app/ru](https://takt-ui.vercel.app/ru). GitHub Actions проверяет pull request и push в `main`. CI выполняет быстрые тесты, ESLint, production-сборку, интеграционные и браузерные проверки. Vercel использует пресет Next.js и команду сборки из `vercel.json`. При каждом push в `main` [публичного репозитория Takt](https://github.com/par1ram/takt-ui) Vercel собирает и публикует production-версию.

У каждого компонента есть английская и русская страницы. Канонические ссылки, языковые альтернативы и `/sitemap.xml` используют production-домен. При смене домена задайте `NEXT_PUBLIC_TAKT_ORIGIN` до сборки. Команда `node scripts/check-seo.mjs https://takt-ui.vercel.app` проверяет опубликованный каталог.

## Разработка библиотеки

- В `components/motion/` находятся редактируемые React-компоненты. Простые переходы реализованы на CSS, жесты и пружинные анимации — с `motion/react`. Magnetic Button использует локальную кнопку shadcn/ui.
- В `registry.json` перечислены исходники и зависимости каждого элемента. Команда `bun run registry:build` собирает установочные JSON-файлы в `public/r/`. После редактирования исходника запустите её, чтобы обновить вкладку с кодом и установочный файл. При запуске dev-сервера и production-сборке реестр собирается автоматически.
- В `lib/catalog.ts` хранятся названия, категории и примеры использования. Привязки к оригинальным названиям позволяют искать компонент по названию референса. Каждый пример подключается отдельным динамическим импортом в `components/catalog/demos.ts`.

Каталог выводит по 12 карточек. Общий IntersectionObserver загружает демо у границ экрана. React Activity отключает эффекты невидимых демо, в том числе в фоновой вкладке, и сохраняет состояние при прокрутке. Исходник из реестра загружается при открытии вкладки с кодом.

Светлая и тёмная темы переключаются в шапке каталога. Выбранная тема и избранные компоненты сохраняются в браузере. Демо учитывают системную настройку уменьшения движения. Референс взаимодействий — [Design Bookmark Motion](https://designbookmark.com/motion).

## Тестирование

Для работы над компонентом запускайте `bun run test`. Полный цикл запускается командой `bun run test:all` после установки браузеров Playwright. [Пирамида тестирования и команды](TESTING.md)

При запущенной production-сборке выполните `bun run motion:review`. Для первого запуска установите Chromium командой `bunx playwright install chromium`. Если установлен Google Chrome, можно выполнить `PLAYWRIGHT_CHANNEL=chrome bun run motion:review`. Адрес каталога задаётся через `MOTION_REVIEW_URL`.

Проверка проходит по всем демо реестра в светлой и тёмной темах. Отдельные сценарии изменяют входные данные уже смонтированного компонента, задерживают и отклоняют запросы и проверяют повторную попытку.

Изменения и результат проверки каждой карточки записаны в [журнале ревизии](COMPONENT-REVIEW.md).

## Исходники для портирования

Команда `bun run motion:sync` обходит публичные карточки DesignBookmark Motion, сохраняет содержимое **Copy code**, точные промты **Claude** и **Codex** и команду установки, если её предлагает автор. Для первого запуска нужен Chrome или Chromium из `bunx playwright install chromium`.

[Карта портирования](references/motion/README.md) связывает референсы с компонентами Takt. У HTML-примера доступны цельный `index.html`, извлечённые стили и скрипты. У React-примера доступны основной TSX и дополнительные файлы, включённые автором в выдачу. [Манифест](references/motion/manifest.json) хранит хеши, зависимости TSX, ссылки на внешние материалы HTML и значения параметров движения, прочитанные в скриптах через `spring()` и `num()`. Поле `licenseNotice` отражает пометку в заголовке исходника.

После прерывания повторите `bun run motion:sync` — готовые карточки берутся из проверенного кеша. Для обновления уже скачанных исходников выполните `bun run motion:sync --refresh`. Команда `bun run motion:verify` проверяет локальный снимок без браузера и интернета. Сырьё для портирования хранится в игнорируемой Git папке `references/motion/sources/`. В shadcn-реестр публикуются компоненты из `components/motion/`.

## Подключение своего агента

Во вкладке **Для агента** в окне установки или исходника есть готовое задание с адресом работающего каталога. Начните с `/llms.txt`. Найдите задачу в `/agents/ru/search.json` и откройте путь из поля `guide`. В карточке есть готовый TSX, варианты пропсов, типы данных, устанавливаемые части и адрес пакета. Английская версия открывается по `/agents/search.json`. Для нестандартного UI-алиаса замените префикс импорта из примера на значение из `components.json`.

Для shadcn MCP добавьте запись в существующий раздел `registries` файла `components.json` потребляющего проекта. При размещении библиотеки подставьте адрес своего сервера. Для удалённого агента укажите доступный ему адрес.

```json
{ "registries": { "@takt": "<публичный URL каталога>/r/{name}.json" } }
```

```sh
bunx shadcn@latest search @takt -q "Assistant Orb"
bunx shadcn@latest view @takt/siri-orb
bunx shadcn@latest add @takt/siri-orb
```

Этим же реестром пользуется официальный [MCP-сервер shadcn](https://ui.shadcn.com/docs/mcp). Например, попросите агента «Найди Assistant Orb в Takt, установи его и свяжи `state` со статусом моего чата. Во время потокового ответа используй `streaming`».

## Card Field в платёжной форме

`<CardField />` в каталоге работает с фиксированным тестовым образцом. В платёжном режиме реквизиты вводятся в размещённое Stripe поле. Takt передаёт приложению только признак заполненности. Для примера ниже приложение создаёт PaymentIntent на сервере и передаёт его клиентский секрет в платёжную форму по HTTPS.

```tsx
"use client";

import { Elements } from "@stripe/react-stripe-js";
import { loadStripe } from "@stripe/stripe-js";
import { CardField } from "@/components/ui/card-field";

const stripe = loadStripe(process.env.NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY!);

export function CheckoutFields({ clientSecret }: { clientSecret: string }) {
  return (
    <Elements stripe={stripe} options={{ clientSecret }}>
      <CardField mode="payment" />
    </Elements>
  );
}
```

Подтверждение платежа через `stripe.confirmPayment` и обработка результата на сервере относятся к checkout приложения. [Документация Stripe Payment Element](https://docs.stripe.com/payments/payment-element)


## Receipt Printer

`<ReceiptPrinter />` запускает локальную демонстрацию. Чтобы подключить checkout, передайте `merchant`, `order={{ id, description, amount, currency }}` и асинхронный `onPay`. Сумма указывается в основных единицах валюты. Обработчик возвращает `{ orderId }` после подтверждения заказа платёжным сервисом. Отклонённый Promise разрешает повторить попытку. На сервере используйте стабильный ключ идемпотентности для одного заказа. Повторная печать использует сохранённый чек. Для следующего заказа поменяйте `order.id`.


Для поля отправки на существующей странице установите Chat Composer. Пример с управляемым черновиком отправляет запрос в обработчик `POST /api/messages` вашего приложения и сохраняет текст для повтора при ошибке. В shadcn MCP найдите пример `chat-composer-demo` в пространстве имён Takt. Его можно установить и командой `bunx shadcn@latest add "$TAKT_ORIGIN/r/ru/chat-composer-demo.json"`. Для отдельного сообщения установите `chat-post`: стили миниатюры поставляются в соседнем файле CSS Module. [Карточка Chat Composer](https://takt-ui.vercel.app/agents/ru/components/chat-composer.json)

При работающем каталоге команда `bun run registry:check http://127.0.0.1:3000` создаёт временный проект, запускает shadcn init, проверяет установку с другим UI-алиасом и повторную отправку в Chromium. Примеры проверяются TypeScript для обеих локалей. Для браузерной проверки установите Chromium для Playwright или задайте `PLAYWRIGHT_CHANNEL=chrome`.
